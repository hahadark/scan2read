# 다음 개발 단계

초기 CLI 기반은 구현되었다. GUI(Tk 기반, PaddleOCR GPU 가속 포함)까지 실행 가능한
상태다. 세션별 상세 변경 이력은 [CHANGELOG.md](CHANGELOG.md) 참고.

## 완료됨 (실제 스캔본 3권으로 검증)

- 반복 머리글·꼬리글 탐지: 위치(상하 15% 여백)로 판단하고, 라벨 텍스트가 매
  챕터 바뀌어도 본문에 박힌 페이지 번호의 오프셋이 일정하면 같은 채널로 인식
  (`cleanup/headers.py`). 성경 구절 인용처럼 우연히 숫자로 끝나는 문장은 오프셋이
  페이지마다 달라 걸리지 않음.
- PDF 자체 텍스트 레이어 재사용(`--text-layer auto`, 기본값): 있으면 OCR을 생략하고,
  인코딩이 깨진 블록만 크롭해 OCR로 보정한다(`pdf/text_layer.py`). "텍스트 레이어
  무시하고 항상 OCR" 체크박스로 강제 재-OCR 가능(원본 PDF의 기존 텍스트 품질이
  낮을 때 유용).
- 각주 제거(opt-in, `--remove-footnotes`), 괄호 안 내용 제거(opt-in,
  `--remove-parentheses`, TTS 레이어 전용 — Clean Text 캐시는 그대로 보존).
- 페이지 범위 지정(`--pages START-END`), 여러 PDF 배치 처리(GUI, 하나가 실패해도
  나머지는 계속 진행).
- NVIDIA GPU 가속(`paddlepaddle-gpu`, 선택적 ~2GB 추가 다운로드): 실측 약 26배
  빠름. `recognition_batch_size=16`으로 추가 ~25% 개선. GPU 사용 시 렌더링/텍스트
  레이어 준비를 별도 프로세스에서 한 페이지 미리 진행하는 프리페치(`pdf/prefetch.py`
  의 `PagePrefetch`)까지 추가됨 — PDFium이 스레드 세이프하지 않아 스레드 대신
  별도 프로세스로 구현, `convert(..., prefetch=True)`는 현재 `--gpu`일 때만 켜짐.
- EPUB 최종 저장 시 XML 금지 제어문자 제거(`epub/builder.py`) — OCR 오인식으로
  생긴 제어문자가 EPUBCheck 이전 단계에서 "not well-formed" 파싱 에러를 내던
  문제 해결.
- GUI 전면 개편: 파일 저장 대화상자 대신 파일 목록(중복 제거, 추가/제거) +
  출력 폴더 선택 + 파일명 규칙(`{name}`/`{folder}`/`{index:03d}`, 실시간 미리보기,
  이름 충돌 시 `(2)`/`(3)` 자동 부여) + 파일별 상태 컬럼(대기/변환 중/완료/실패/
  중단/취소). 모든 설정(출력 폴더, 이름 규칙, 단 수, 페이지 범위, 보정 옵션, GPU
  사용 여부)은 `%LOCALAPPDATA%\Scan2Read\settings.json`에 자동 저장·복원됨
  (`project/batch.py`의 `Preferences`). 드래그 앤 드롭, "결과 파일 위치 열기"(폴더가
  아니라 파일 자체를 탐색기에서 선택).
- 캐시 식별자에 `text_layer` 모드(`auto`/`off`) 포함 — 모드를 바꾸면 별도 캐시를
  쓰고, 모드 정보가 없는 예전 캐시는 재사용하지 않고 한 번만 다시 처리하며 경고
  로그를 남김. 괄호 제거는 Clean Text 저장 이후 `tts_paragraphs()`에서만 적용해
  Clean Text 캐시에는 항상 원본 괄호가 남음.
- 각주 탐지 고도화: 페이지 중간부터 시작하는 긴 각주, 번호 뒤 공백이 없는 각주,
  하단에 분리된 무번호 각주(다음 페이지로 이어지는 각주 포함), 본문 줄 끝에 붙은
  위첨자 각주 표시(대응하는 같은 페이지 각주가 있을 때만 제거)까지 처리
  (`cleanup/footnotes.py`).
- 고립된 1~2글자 잡음 제거(`cleanup/noise.py`): 장식용 구분 기호 오인식, 삽화
  캡션·저작권 표시 잔여물, 스캔 가장자리 흐림, 검출기 잡티(먼지 등)처럼 반복되지
  않아 헤더/각주 탐지로는 못 잡는 한 번뿐인 잡음을 제거. 다른 블록과 전혀 병합되지
  않은 블록에만 적용하며, 한글·숫자·로마 숫자가 있으면 절대 지우지 않음.
- PDF 텍스트 레이어의 단어/구간 단위 블록을 좌표로 시각적 줄에 먼저 합친 뒤,
  줄 간격·들여쓰기와 로컬 Kiwi 문맥 판정으로 문단을 복원함. `고대 근동 역사`
  482쪽의 113,853개 원본 블록을 4,742개 문단으로 정리했고, 원본 블록과 결과의
  공백 외 글자가 모두 일치하는지 검사함(`cleanup/reconstruction.py`,
  `cleanup/context.py`).

## 남은 항목

1. 작은 실제 스캔 발췌본으로 오류 수집: 문장 누락, 잘못된 띄어쓰기, 페이지 경계
   끊김을 구분하고 익명화한 회귀 fixture 추가.
2. 문단 및 페이지 경계 연결 개선: 인용문·대화·들여쓰기·문장부호를 검증하면서
   보수적으로 적용.
3. 캐시 손상 복구와 동시 실행 잠금, 처리 상태 명령 추가.
4. 일반 EPUB 리더 및 모바일 TTS로 연속 낭독 검증. 100~500페이지 성능·재개 실험.
5. 목차(ToC) 페이지의 점선·페이지번호 나열이 문단별로 쪼개져 어색하게 낭독되는
   문제 — 표 형태 레이아웃이라 이번 범위에서 제외.
6. 한국어 인식 모델은 PaddleOCR에 "mobile" 크기만 존재(서버·PP-OCRv6 모델 없음).
   "meditation"→"medilation" 같은 반복 오인식은 모델 자체 한계라 코드로는 못
   고치며, 새 모델이 나오길 기다리거나 다른 OCR 엔진과 비교하는 수밖에 없다.

성경구절 변환, 외부 AI, 음성 생성, M4B, 복잡한 표와 2단 복원은 이번 기반 구현에서 제외했다.
