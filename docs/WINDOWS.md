Scan2Read 0.1.0 — Windows 사용 안내

`Scan2Read-Setup.exe`를 실행하고 설치 버튼을 누르세요. 관리자 권한은 필요하지 않습니다.
설치 파일은 약 123MB이며, 설치 중 CPU용 PaddleOCR·Kiwi와 한국어 OCR 모델 약
250MB를 공식 Paddle 저장소와 PyPI에서 내려받습니다. 인터넷 연결이 필요하고,
설치가 끝난 뒤 디스크 사용량은 약 1.2GB입니다. NVIDIA CUDA 구성요소는 기본
설치에 포함하지 않으며 GUI에서 GPU 가속을 선택할 때만 별도로 받습니다.
설치 후 시작 메뉴의 Scan2Read를 실행하세요.

화면은 "변환"(파일 목록, 시작/중단, 로그) · "변환 설정"(출력 폴더, 파일명 규칙, 단 수,
보정 옵션, GPU, 동시 처리 개수) · "AI 설정"(제공자·모델·키·기능·비용) 3개 탭으로
나뉘며, Windows 11 스타일의 밝은 테마(Sun Valley)로 디자인했습니다. 화면 배율(HiDPI)을
자동으로 인식해 고해상도 모니터에서도 흐릿하지 않고 적절한 크기로 표시됩니다.

1. "변환" 탭에서 PDF 추가·폴더 추가 또는 드래그 앤 드롭으로 파일을 목록에 추가합니다. PDF가 있는 폴더를 창에 끌어다 놓으면 그 폴더 바로 아래의 PDF를 이름순으로 추가합니다(하위 폴더는 자동 탐색하지 않습니다). 여러 번 추가할 수 있으며 같은 파일은 중복 추가하지 않습니다. 선택 제거·목록 비우기 버튼으로 정리합니다.
2. "변환 설정" 탭에서 출력 폴더를 선택합니다. 대화상자에서는 폴더만 선택하며 파일 이름을 입력하지 않습니다. 비워두면 각 원본 PDF와 같은 폴더를 사용합니다.
3. 파일명 규칙을 지정합니다. {name}은 원본 이름, {folder}는 원본 폴더명, {index:03d}는 001부터 시작하는 번호입니다. 예: {name}_낭독용 또는 {index:03d}_{name}. 목록에서 저장될 이름을 미리 확인합니다. 기존 파일이나 목록의 이름과 겹치면 (2), (3) 등을 붙입니다.
3. 책의 본문에 맞게 1단(기본값) 또는 2단을 선택합니다. 필요하면 각주를 제거하는 옵션도 켤 수 있습니다.
4. 전체가 아니라 일부 페이지만 처리하려면 "처리할 페이지 범위"에 "30-50"처럼 입력합니다. 비워두면 전체 페이지를 처리합니다.
5. "변환" 탭으로 돌아와 변환 시작 / 재개를 누릅니다.
6. 완료되면 "결과 파일 위치 열기"로 탐색기에서 EPUB을 바로 찾아 전자책 앱으로 옮깁니다.

PaddleOCR 한국어 모델, Kiwi 띄어쓰기 보정, Python, Java, EPUBCheck를 포함합니다.
변환은 로컬 PC에서 실행하며 API 키나 유료 AI 서비스가 필요하지 않습니다.

"AI 설정" 탭에서 `AI 기능 전체 사용`을 켜면 애매한 문단 경계 판정 등을 AI로 보강할 수 있습니다.
제공자(OpenAI/Claude/Gemini)와 모델을 책 전체에 하나씩 고르고, 그 제공자의 API 키를
입력합니다(키는 설정 파일이 아니라 제공자별로 암호화된 별도 파일에 저장). 모델은
GPT-5.6 Luna(기본값)·Terra, Claude Fable 5.1·Opus 5·Sonnet 5·Haiku 4.5,
Gemini 3.8/3.6 Flash·2.5 Pro/Flash/Flash-Lite 중에서 고르며, 선택한 모델의 백만 토큰당
요금이 바로 아래에 표시됩니다. 기본값은 저렴한 모델입니다 — 실제로 5쪽을 측정해 보니 같은
정리 작업에 비싼 모델이 Luna의 13~36배를 쓰면서 품질 이득은 그만큼이 아니어서, 가장 비싼
GPT 모델들은 목록에서 뺐습니다. 목록에 없는 모델 ID를 직접 입력할 수도 있는데, 이때는
요금을 알 수 없어 그 제공자의 가장 비싼 요금 기준으로 비용을 추정하며 경고가
표시됩니다. 키가 없거나 API 요청이 실패하면 그 변환의
나머지 작업은 로컬 판정으로 계속됩니다. 응답이 잘못된 경우는 그 요청 묶음만 로컬로 넘어가고
다음 묶음은 다시 시도하며, 연결 자체가 끊긴 경우에만 그 책의 나머지 전체가 로컬로 전환됩니다.
변환 중에는 처리된 묶음 수와 예상 남은 시간이 화면에 표시됩니다.
OCR 결과는 완벽하지 않으므로 중요한 내용은 원본과 대조하세요.
PDF에 이미 텍스트 레이어가 있으면(예: Word에서 내보낸 PDF) OCR 없이 그 텍스트를 그대로 사용하며, 인코딩이 깨진 부분만 골라 OCR로 보정합니다. 텍스트 레이어가 없는 스캔 이미지는 기존처럼 OCR을 수행합니다. 파일을 선택하면 텍스트 레이어 감지 결과를 먼저 보여줍니다.
"문맥·줄바꿈·문단 보정"은 단어 단위로 잘게 나뉜 PDF 텍스트를 좌표로 한 줄로 모으고, 줄 길이·들여쓰기·간격과 로컬 Kiwi 형태소 분석으로 문장이 끝날 수 없는 경계를 연결합니다. 완결된 문장·제목·목록은 따로 두며 인터넷이나 API를 사용하지 않습니다. Raw OCR은 그대로 보존됩니다.
"주석 제거"는 페이지 하단의 각주로 보이는 문단을 제거하는 실험적 옵션으로, 기본값은 꺼짐입니다. 위치와 번호·기호로 시작하는지, 본문보다 작은 글자인지를 보고 판단하므로 드물게 각주가 아닌 문단을 지우거나 형식이 다른 각주를 놓칠 수 있습니다.
현재 화면의 이름은 "각주 제거"입니다. 페이지 중간부터 이어지는 긴 각주, 번호 뒤에 공백이 없는 각주, 아래쪽에 분리된 작은 글자로 이어지는 무번호 각주도 판정합니다. 본문에 섞인 인용이나 책 뒤에 모인 미주는 이 옵션의 대상이 아닙니다.
"괄호 안 내용 제거"는 "지라(계2:5)"처럼 괄호로 묶인 성경 구절 인용 등을 낭독용 텍스트에서만 빼는 옵션입니다(원본·정리된 텍스트 캐시는 그대로 보존). 기본값은 꺼짐이며, 한 문단에서 괄호 개수가 안 맞으면(OCR 오류 등) 그 문단은 손대지 않습니다.
이 로컬 옵션은 괄호가 정확히 짝지어졌을 때만 동작합니다. 히브리어·그리스어 원문을 다루는
책은 "체다카"처럼 원어를 한글로 음역해 괄호로 병기하는 경우가 많은데, 이 괄호가 OCR로
깨지면(짝이 안 맞으면) 로컬 옵션은 안전하게 그 문단을 건드리지 않고 넘어갑니다. "AI 설정"
탭의 "괄호·음역 중복 표현 삭제"를 함께 켜면, AI가 "정의(체다카)"처럼 바로 앞뒤 낱말과 뜻이
같아 소리 내어 읽으면 반복되는 음역 표현을 찾아 지웁니다 — 괄호가 깨진 경우도 포함해서
판단합니다. 이 기능도 원본 후보를 정확히 한 번만 찾을 수 있을 때, 그리고 문단의 1/3을
넘지 않는 짧은 부분일 때만 적용하며, 애매하면 그 문단은 그대로 둡니다.
"텍스트 레이어 무시하고 항상 OCR"은 PDF에 이미 텍스트가 있어도 그걸 믿지 않고 Scan2Read가 직접 OCR로 다시 읽게 합니다. 원본 PDF의 텍스트 품질이 낮을 때(다른 프로그램의 OCR 결과가 포함된 PDF 등) 켜면 도움이 됩니다.

NVIDIA GPU가 있는 PC에서는 "GPU 가속 다운로드" 버튼이 나타납니다. 누르면 NVIDIA CUDA
런타임(약 2GB)을 내려받아 설치하며, 설치 후에는 "GPU 가속 사용" 체크박스로 켜고 끌 수
있습니다. GPU는 CPU보다 수십 배 빠르지만 부동소수점 연산 차이로 아주 드물게 인식 결과가
CPU와 미세하게 달라질 수 있어, 기기를 바꾸면 해당 페이지의 캐시된 OCR을 재사용하지 않고
새로 처리합니다. NVIDIA GPU가 없는 PC에는 이 버튼이 나타나지 않으며, 추가로 내려받지
않는 한 설치 용량에는 영향이 없습니다.
GPU 변환에서는 현재 페이지를 인식하는 동안 별도 프로세스가 다음 페이지 하나만 미리
렌더링합니다. 실제 8페이지 반복 시험에서 렌더링과 OCR 시간이 약 23% 줄었으며, 이미지와
OCR 결과는 기존 방식과 동일했습니다. 책과 PC 상태에 따라 개선 폭은 달라질 수 있습니다.
GPU가 감지되면 "변환 설정" 탭에 실시간 GPU 사용률과 VRAM 사용량이 표시됩니다.

"변환 설정" 탭의 "동시 처리 개수"(1~4, 기본값 2)로 한 번에 몇 개의 OCR 프로세스를 동시에
돌릴지 정합니다. 값이 클수록 GPU 메모리를 그만큼 더 씁니다(프로세스마다 독립적으로 모델을
올리기 때문). 2 이상으로 두면 큰 책은 페이지 구간을 나눠 여러 프로세스가 동시에 OCR하고,
모든 구간이 끝나면 자동으로 EPUB을 조립합니다 — 목록에는 "OCR 320/554쪽"처럼 진행 상황이
표시됩니다. 파일이 여러 권이면 한 파일의 구간들과 다른 파일의 조립 작업이 같은 동시 처리
개수 안에서 섞여 돕니다. 값을 1로 두면 지금까지와 동일하게 파일당 하나씩 순서대로
처리합니다. GPU 메모리가 부족하면 값을 낮추세요.

여러 파일을 한 번에 처리할 때 하나가 실패해도 나머지는 계속 진행하며, 끝나면 몇 개가 성공했는지 알려줍니다. "중단"을 누르면 지금 처리 중인 모든 작업을 멈추고 나머지 대기열은 취소됩니다("결과 파일 위치 열기"는 마지막으로 완료된 파일을 엽니다).
목록에는 파일별 대기·(OCR 진행률 또는 EPUB 조립 중)·완료·실패·중단·취소 상태가 표시됩니다. 완료하거나 중단해도 목록은 남습니다. 페이지 범위와 보정 설정은 목록의 모든 파일에 적용합니다.

출력 폴더, 이름 규칙, 단 수, 페이지 범위, 보정 옵션, GPU 사용 선택은 변경 후 자동 저장되며 다음 실행 때 복원됩니다. 설정 파일은 %LOCALAPPDATA%\Scan2Read\settings.json 입니다.

중단 후 같은 설정으로 재개하면 완료된 페이지의 OCR을 재사용합니다.
캐시는 %LOCALAPPDATA%\Scan2Read\work 에 저장합니다.
원본 OCR은 보정 결과와 분리하여 보존합니다.
프로그램을 제거해도 EPUB과 OCR 캐시는 보존합니다.

Windows x64용이며 이 PC에서 검증한 초기 배포본입니다.
개발자 인증서로 서명되지 않았습니다.
